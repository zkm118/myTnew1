# Requirements Document

## Introduction

终端用户在小程序中完成智能设备绑定后，需要在小程序内查看该设备产生的数据。本功能按「物模型驱动」构建通用的设备数据界面：列表、详情、历史与趋势均由产品级展示配置驱动，体脂秤是首个落地的设备类型，后续接入其他智能设备时无需改动客户端数据框架。

## Glossary

- **终端用户**：通过手机号验证码登录小程序的 `user` 角色用户。
- **设备类型**：产品的品类标识（如体脂秤、温湿度计、插座），用于选择界面模板。
- **智能设备**：接入平台的消费级设备，其能力由所属产品的物模型定义。
- **物模型**：产品级能力描述，包含属性、事件与服务，是数据校验、展示与下发的统一依据。
- **设备数据记录**：按 MQTT 消息 `id` 聚合而成的一次设备上报集合，包含一条或多条属性值。
- **展示配置**：产品级配置，声明主指标、次要指标与趋势指标，驱动客户端界面的动态渲染。
- **绑定关系**：终端用户与某台设备之间的有效归属记录，由设备接入模块维护。
- **小程序**：uni-app 编译的微信小程序端。
- **系统**：link_equipment 平台，含 FastAPI 后端与小程序客户端。

## Requirements

### Requirement 1: 已绑定设备入口

**User Story:** AS 终端用户, I want 在小程序中看到自己已绑定的设备, so that 我能进入该设备的数据页面。

#### Acceptance Criteria

1. WHEN 终端用户完成登录且存在至少一条有效绑定关系, THE 系统 SHALL 在小程序设备列表中展示该用户已绑定的全部设备，包含设备名称、设备类型与在线状态。
2. WHEN 终端用户点击列表中的一台已绑定设备, THE 系统 SHALL 根据该设备所属产品的设备类型进入对应的数据详情页。
3. IF 终端用户当前没有有效绑定关系, THE 系统 SHALL 展示空状态并提供「添加设备」入口。
4. IF 某台已绑定设备的产品类型尚无专用界面模板, THE 系统 SHALL 使用通用模板按物模型属性渲染数据。

### Requirement 2: 设备数据记录展示

**User Story:** AS 终端用户, I want 打开设备详情后立刻看到最近一次上报结果, so that 我能快速了解设备当前状态。

#### Acceptance Criteria

1. WHEN 终端用户打开已绑定设备的数据详情页, THE 系统 SHALL 展示该设备最近一次数据记录的上报时间与属性值。
2. WHILE 最近一次数据记录存在, THE 系统 SHALL 按该产品展示配置中的主指标与次要指标展示属性值。
3. IF 展示配置中的某个指标在该次记录中未上报, THE 系统 SHALL 以「--」占位展示该指标。
4. IF 该设备尚无任何数据记录, THE 系统 SHALL 展示「暂无数据」提示。

### Requirement 3: 历史数据记录查询

**User Story:** AS 终端用户, I want 按时间查看设备历史数据, so that 我能追踪设备的使用与变化。

#### Acceptance Criteria

1. WHEN 终端用户进入数据详情页且未更改时间范围, THE 系统 SHALL 以近 30 天作为默认查询区间。
2. WHEN 终端用户选择时间范围, THE 系统 SHALL 返回该范围内、属于该绑定设备的全部数据记录，按记录时间倒序排列。
3. WHEN 数据记录超过单页容量, THE 系统 SHALL 以分页方式返回，默认每页 20 条。
4. WHILE 终端用户查看历史记录, THE 系统 SHALL 按展示配置中的指标集合展示每条记录的属性值。
5. IF 所选时间范围内没有数据记录, THE 系统 SHALL 展示「该时间段暂无数据」提示。

### Requirement 4: 趋势图

**User Story:** AS 终端用户, I want 看到关键指标随时间变化的曲线, so that 我能直观观察趋势。

#### Acceptance Criteria

1. WHEN 终端用户打开数据详情页且所选时间范围内某个趋势指标存在不少于 2 条数据, THE 系统 SHALL 展示该指标的趋势图。
2. WHEN 产品的展示配置声明了多个趋势指标, THE 系统 SHALL 为每个满足条件的指标分别展示趋势图。
3. IF 某个趋势指标可绘图的数据点少于 2 个, THE 系统 SHALL 隐藏对应趋势图并保留列表展示。

### Requirement 5: 数据归属与权限

**User Story:** AS 终端用户, I want 只能看到自己绑定设备的数据, so that 我的设备数据不被他人查看。

#### Acceptance Criteria

1. WHEN 终端用户请求某台设备的数据, THE 系统 SHALL 校验当前登录用户与该设备存在有效绑定关系后，返回该设备上的全部数据记录。
2. IF 当前登录用户与目标设备不存在有效绑定关系, THE 系统 SHALL 返回 403 并拒绝返回任何数据。
3. IF 访问令牌缺失或失效, THE 系统 SHALL 返回 401 并引导小程序重新登录。

### Requirement 6: 数据时效

**User Story:** AS 终端用户, I want 设备上报后尽快在小程序看到数据, so that 我确认本次上报已同步。

#### Acceptance Criteria

1. WHEN 已绑定设备成功上报一次数据记录, THE 系统 SHALL 在 10 秒内使该记录可通过小程序数据接口查询。
2. WHEN 终端用户在数据详情页执行下拉刷新, THE 系统 SHALL 重新拉取最近一次数据记录与当前时间范围的历史列表。

### Requirement 7: 设备类型扩展

**User Story:** AS 平台管理员, I want 新增设备类型时无需改动客户端数据框架, so that 平台能以低成本接入更多品类。

#### Acceptance Criteria

1. WHEN 平台新增一个产品并在其物模型与展示配置中声明指标, THE 系统 SHALL 在终端用户绑定该产品设备后，按声明自动渲染数据界面。
2. WHILE 新增设备类型的展示配置使用通用指标字段, THE 系统 SHALL 复用同一套数据记录接口，不新增设备类型专属接口。
3. WHEN 某设备类型需要专属交互（如体脂秤的称重引导）, THE 系统 SHALL 通过专用界面模板实现，并保留通用模板作为回退。
4. IF 产品未配置展示配置, THE 系统 SHALL 按物模型中只读属性的前若干项生成默认展示配置。
