# 设备类型与展示配置

## 概念

**设备类型**（device category）是产品的品类标识，用于决定客户端采用哪套界面模板展示设备数据。**展示配置**（display config）挂载在产品上，声明该品类要展示哪些指标、画哪些趋势，是客户端界面的数据源。

两者共同支撑「物模型驱动」的通用数据界面：平台侧配置产品，客户端自动渲染，无需为每个品类单独开发数据框架。

## 关注点分离

| 概念 | 归属 | 回答的问题 |
|------|------|-----------|
| 物模型 | 产品 | 设备有哪些能力（属性、事件、服务） |
| 设备类型 `category` | 产品 | 这是什么品类的设备 |
| 界面模板 `template` | 产品 | 客户端用哪套页面展示 |
| 展示配置 `display_config` | 产品 | 界面展示哪些指标、画哪些趋势 |

## 展示配置结构

```json
{
  "primary_metrics": ["weight"],
  "secondary_metrics": ["body_fat", "muscle_mass", "body_water"],
  "trend_metrics": ["weight", "body_fat"],
  "list_metrics": ["weight", "body_fat", "muscle_mass", "body_water"],
  "template": "body_scale"
}
```

| 字段 | 说明 |
|------|------|
| `primary_metrics` | 详情页主指标，取首个作为大数值展示 |
| `secondary_metrics` | 详情页次要指标，网格展示 |
| `trend_metrics` | 需要绘制趋势图的指标 |
| `list_metrics` | 历史列表每行展示的指标 |
| `template` | 客户端界面模板标识，缺省为通用模板 |

指标值取自物模型属性标识符，名称与单位由物模型提供。

## 默认生成规则

产品未配置展示配置时，按物模型生成：

1. 取 `access_mode` 为 `r` 或 `rw` 的属性。
2. 数值型（`int` / `float`）前 3 项作为 `trend_metrics`。
3. 首个属性作为 `primary_metrics`。
4. 其余属性进入 `secondary_metrics` 与 `list_metrics`。
5. `template` 使用通用模板。

## 设备类型示例

| 设备类型 | category | 主指标 | 趋势指标 |
|---------|----------|--------|---------|
| 体脂秤 | `body_scale` | `weight` | `weight`、`body_fat` |
| 温湿度计 | `thermo_hygrometer` | `temperature` | `temperature`、`humidity` |
| 智能插座 | `smart_plug` | `power` | `power` |

## 扩展流程

```mermaid
graph LR
    A["创建产品与物模型"] --> B["配置展示配置"]
    B --> C["设备接入并上报"]
    C --> D["小程序按配置自动渲染"]
```

新增品类只需配置产品；仅当需要专属交互（如体脂秤称重引导）时才新增界面模板，且内部复用通用组件。
